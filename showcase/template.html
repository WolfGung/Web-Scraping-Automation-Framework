How it is put together

The architecture and pipeline diagrams ship with the published build of this page; this copy was generated without them.

Which door each source goes through, and why

A browser is the expensive answer, so it is used where it is the only answer and nowhere else. The choice is per source and it is defended by a test, not by a preference.

books.toscrape.com — plain HTTP

The catalogue is server-rendered, so src/scrapewatch/sources/books.py walks it with the HTTP client alone: no browser starts, and a thousand books cost fifty requests instead of fifty page loads. Choosing not to start a browser is the engineering decision here, and the parsers are proven against pages saved from the real site under tests/fixtures/books/, so the gate can check them with no network and no flakiness.

quotes.toscrape.com — a browser, because nothing else can see the page

The site's /js/ page ships its quotes as a JSON array inside a <script> block and renders them with client-side JavaScript, so anything that only speaks HTTP sees an empty page. tests/parsers/test_quotes_parser.py is the proof rather than the claim: the same parser finds nothing in the raw fetched page and every quote in what the browser rendered.

The demo store — a target that changes on purpose

Change detection cannot be demonstrated against a catalogue that never moves, and it must not be demonstrated by editing the database by hand. The store in src/scrapewatch/demo_store/ derives every price and stock level from the date with a seeded rule, so two runs on two days genuinely differ and the same day always reproduces. It also carries the infinite-scroll page the browser engine is exercised against, and a login wall, so a session-only view has somewhere to exist.

What it deliberately does not do

Out of scope, by decision

  • Anti-bot evasion. No fingerprint spoofing, no stealth plugins, no captcha solving. The scraper identifies itself by name in its User-Agent and links back to the repository.
  • Proxy rotation. One origin, one honest address. Rotating addresses to get around a rate limit is the opposite of the politeness the client is built around.
  • Speed. Nothing here is tuned for throughput. There is a minimum interval between two requests to the same host and a bounded retry budget, and both are floors on politeness rather than ceilings on performance.
  • Sites beyond the three named. Two public practice sites that exist to be scraped, and a store that ships in this repository. Pointing this at anything else is a decision for whoever does it.
  • A scheduler inside the application. The night's run is a cron entry in the pipeline, not a daemon in the code. A tool that scrapes when it is asked is much easier to reason about than one that scrapes on its own.

Four decisions that keep it honest

Politeness lives in the client, not in each source

src/scrapewatch/http.py reads robots.txt before it fetches anything from an origin, keeps a minimum interval between requests to that host, retries on its own budget, and counts every request, retry and byte. A source that forgot to be polite is not possible, because a source does not make requests — the client does. A site whose robots.txt cannot be read at all is treated as disallowed: a scraper that cannot read the rules does not get to assume there are none.

One bad record costs itself, not the night

src/scrapewatch/pipeline/run.py normalises record by record and isolates the failures, so one malformed listing out of a thousand is counted as a parse error and named in the run statistics while the other 999 — some of which may carry the very price change this tool exists to find — are still snapshotted. A source is only "skipped" when it produced nothing usable at all, and that is a different sentence on this page.

Snapshots are kept, not overwritten; the diff compares the last two

src/scrapewatch/storage.py never writes over yesterday. Records are matched across snapshots by the identifier the site gives them — a slug, a product id — so a catalogue that reorders itself is not reported as a thousand changes, and a price that moved is reported as the one field that moved, with its before and after. The history is bounded on purpose: the last {{RETENTION}} snapshots of every source are kept and the rest are pruned after each run, because this database is published and an unbounded one eventually cannot be.

The gate never touches the network

Parsing is proven against pages saved from the real sites and dated, in tests/fixtures/. That is what makes a red live check meaningful: the fixtures still parse and the live page no longer does, which is markup drift and not an outage. The night's run reaches the sites; a push never does.
